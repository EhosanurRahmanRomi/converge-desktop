## Changes in 1.4

- **Source-code media support:** supported plain-text source extensions include `.mq5` and `.mqh`. Real generated source downloads are captured, checked and attached to the peer. Binary executables and unknown formats remain unsupported. Uploaded source is not executed by Converge.
- **Conservative deliverable inference:** an explicit revision/delivery request for attached code requires the complete source download even with the file checkbox off. MQL5 code inside `.txt` is recognized from a bounded private prefix, including UTF-16 with a BOM. Ordinary explanations and analysis-only reviews do not gain a file requirement. The next unrelated command clears the inferred code/file requirements.
- **Exact byte identity:** required code candidates need an exported SHA-256 and byte count. Prose, filenames and fabricated links do not satisfy the output gate. Renaming unchanged bytes or changing only the explanation cannot count as a revised EA. A missing output receives one bounded creation follow-up, then stops as unfinished if still absent.
- **Safe text upload copies:** a generated `candidate.mq5` reaches the receiving chat as `candidate.mq5.txt` containing exactly the same bytes. Original source copies similarly use `ORIGINAL_SOURCE_1__original.mq5.txt`. Prompts explicitly map names and candidate identity. The original download name remains in candidate metadata and Save writes `.mq5`, not the upload alias. Conflicting alias names are rejected before ambiguous source uploads.
- **Complete readable code readbacks:** the large-code review path combines shorter task-specific review directions with complete readable current-candidate JSON containing candidate ID, original filename, attached-byte SHA-256 and byte count. The app checks those bytes before submission. A reviewer can inspect and manually trace the visible code even when the provider's attachment index fails. For parser readback, literal editor-added U+00A0 nonbreaking spaces must be normalized to ASCII spaces **before** parsing JSON; genuine source nonbreaking spaces are escaped as `\u00a0` and preserved. A decoded text digest need not match a UTF-16 file's byte digest; original byte identity remains authoritative. This supplies source for inspection and does not establish native compilation or backtesting.
- **Original task provenance:** large code reviews refer to the original attachments supplied to both independent drafts and the reviewers' actual prior inspection, instead of repeating every original code file in each review message. They require honest disclosure of original-source access limitations. Non-text originals are still reattached. The ordinary small-text path supplies escaped complete original snapshots, rather than treating a rewritten candidate as the task source.
- **Bounded messages and remaining snapshot formats:** raw source records remain bounded to 40,000 decoded characters per file, 60,000 combined, and 120,000 characters of JSON. Records are complete files, never truncated excerpts; files outside those bounds need actual attachment access. Some snapshot paths still escape spaces or use `gzip-base64-json` for long text, with a required available-tool decoder. The current large-code assignment and candidate source are readable; the failed whole-assignment `gzip-base64-utf8` wrapper has been removed. Large readable-code reviews have a 64,000-character app budget; ordinary messages retain 48,000. Messages beyond their applicable budget fail before submission, retain files/chats and explain the limit. A larger app budget does not guarantee provider acceptance.
- **Provider rejection handling:** the page bridge recognizes a fresh message-length or generation error belonging to the submitted request, including the observed rejection that leaves a Stop control visible. It stops with the provider reason and keeps the chat; it does not automatically submit the request a second time. An old error elsewhere on the page cannot fail a new successful request.
- **Native download ownership and timing:** the recorded release extends bounded download/export timing past the former 15/20/35-second races and retains the owning IPC request during sequential exports. The real R10 draft downloads succeeded automatically in both correct embedded WebContents. An earlier late-blob race had triggered an unexpected Save dialog; that failure is recorded rather than counted as a successful automatic capture.
- **Code-specific supervision:** inspect the complete original implementation, requested behaviors, units and platform APIs. Preserve complete runnable source. For MQL5, check risk/lot normalization, broker stops/volume constraints, account currency conversion, tick values, indicator buffers, closed-bar timing, trade return codes and safe stop updates. PDF worksheet/equation-specific production instructions no longer replace code-file instructions.
- **Persistent essential-work ledger:** requested native MT5 backtests remain requirements across replacements. Explicit native compilation requests are tracked separately. Reviewers cannot waive them by agreeing tools are unavailable, marking an issue ID resolved, deleting uncertainties, or rewriting the answer as a research-only candidate. Bounded stalled/round-limit endings preserve the useful current files and show unfinished work.
- **Candidate-specific reported evidence:** a completed backtest claim needs the exact candidate source digest, an actual captured report artifact, broker/symbol/timeframe, valid dates covering the requested months, tick/data model, costs and observed results. Compilation claims need the exact source digest, captured compiler log and a reported native zero-error result. Both reviewers must supply this evidence for the current candidate. Any replacement invalidates the earlier evidence.
- **Report-format recovery:** optional task evidence does not add a strict-schema failure to ordinary tasks. Missing/malformed evidence leaves required work unfinished. Format-only issue repair must preserve task evidence, including unavailable statuses and field presence; it cannot create completion claims.
- **Result wording:** native-test metadata and captured report bytes are labeled as reported evidence. They are not independently authenticated native trading performance.

## Interpretation and remaining limits

There are separate questions: whether the app sent the exact files, whether reviewers performed useful checks, whether the revised source is correct, and whether a native MT5 test establishes the requested performance. Passing the first does not establish the others.

The essential-work gate checks attached file identity and the structure/coverage of **model-reported** evidence. Converge does not launch MetaEditor/MT5, verify broker history, authenticate tester provenance or independently reproduce a report. A plausible fabricated report can still satisfy metadata checks; the result must remain labeled as reported evidence unless native execution and independent review actually occur. A genuine attached native report also needs correct settings and an appropriate independent evaluation before treating trading claims as proven.

Code edits can address concrete implementation defects. They cannot by themselves establish profitability, win rate, low drawdown or retained trade frequency. The supplied code's daily trade limit is a ceiling rather than a measured baseline. No universal profitability or correctness promise is made.

Earlier live 1.3 tests demonstrated real code and image refinement, but also model-agreement false positives on a physics worksheet and a scheduling explanation. Those historical results remain in `docs/browser-studio-1.3-verification.md`; they are not fresh verification of 1.4.

Independent task-specific tests and human/subject review remain necessary when answer quality matters. Official OpenAI documentation recommends representative evaluation cases, defined success criteria, repeated comparison and calibration against human judgment. This release uses the observed EA-file failure as a targeted regression case. [OpenAI Docs: evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices).

Original and candidate attachments together remain limited to five files, 12 MB each and 24 MB total. The smaller source-readback/prompt limits above apply separately. The current large-code path supplies readable source; any other compressed snapshot still needs an actual usable decoder, and a reviewer must disclose inability to inspect original attachments. Provider context and message limits still apply.

Private original bytes are cleared on completion, Stop, failure, Reset and the next command. Reattach sources for a new task that needs them. Completed candidate files remain available for explicit Save on bounded unfinished endings. Expired downloads/cookies, account limits, provider tool failures or changed ChatGPT markup can stop an exchange.
